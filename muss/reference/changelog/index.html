The changelog

All notable changes to this workspace are recorded here.

The format follows Keep a Changelog, and the versioning follows Semantic Versioning. The three crates — muss-core, muss-teams and muss-teams-cli — are released together and share one version number.

Nothing has been published yet. The crates are not on crates.io, so there is no released version to compare against, and the section below holds everything that has landed since the workspace was created.

Unreleased

Section titled “Unreleased”

Added

Section titled “Added”
  • muss-core — shared Microsoft 365 primitives: typed tenant identity and AuthContext, credential providers with audience-separated token clients, a pooled and bounded HTTP transport with a retry policy, the shared error taxonomy, UUID-v4 idempotency keys, secret redaction and telemetry hooks.
  • muss-teams — a framework-neutral Microsoft Teams SDK behind one facade: authenticated bot activities, interactive Adaptive Cards, proactive messages, Graph notifications, dialogs, extensions, user sign-in, meetings and presence.
  • muss-teams-cli — a companion binary that scaffolds a project, validates an app manifest, packages a Teams app and diagnoses a configuration. It is never required at runtime.
  • Teams user sign-in: silent SSO, a state-and-PKCE fallback, sealed per-person sessions that carry a key id so a rotation can keep the previous key, and a delegated Graph feed.
  • Adaptive Card builders, action handling and typed card responses, with fallbacks across columns, table rows and table cells.
  • Tenant-scoped state with idempotent execution and an outbox, in memory or in SQLite, with a fair scheduler that forgets a drained tenant.
  • A typed Graph client with bounded paging, throttle handling and OData-error handling, plus the directory and app-install helpers.
  • The muss-teams crate’s feature matrix: http-host, sqlite, graph, sso and test-utils, with the lean outbound-only combination available as --no-default-features.
  • A documentation site published from docs/.
  • A check that the pages the site publishes are the pages the repository’s documents produce. Two scripts generate the site’s pages from the repository’s documents, and both were run by hand, so a change under docs/ could sit in the repository while the published site still said the old thing. The check runs the generators in a scratch copy of the tree and compares the result against the published pages, so a stale page fails the build rather than reaching a reader.
  • TeamsError::UnusableResponse — the service accepted a request and answered with a body the SDK cannot read. It is distinct from a transport failure, which means the request never reached the service.
  • A tracked commit-msg git hook and the installer that puts it in place. The hook refuses a commit message carrying an agent/tool attribution trailer, because the history belongs to the person who made the changes. The hook lives in scripts/hooks/ rather than in one machine’s .git/hooks, and scripts/ci/check-commit-msg-hook.sh proves that it refuses what it claims to refuse and that the installer keeps a hook that was already on the machine and lets it refuse the commit first.

Fixed

Section titled “Fixed”
  • The documentation no longer claims capabilities the SDK does not have. The crate description, the crate’s rustdoc, the two READMEs and the public API document all said the SDK covered “supported file flows” and “a documented TeamsJS bridge”. Neither is implemented: no file is uploaded or downloaded, no fileConsent activity is answered, and there is no bridge. A reader choosing a library would have found the gap after installing it. The claims now say what the SDK does, and file transfer and the browser-side frontend are listed as not in v1 with the reason.
  • The transport no longer carries a credential rule that nothing consulted. may_present_credential decided whether an Authorization header could be presented to an origin, and it was called only by its own tests: the rule that actually governs a redirect lives in redirect_is_allowed and in reqwest, which strips the credential headers itself when the host or the effective port changes. The function is gone.
  • The transport refuses to send a request in clear text to a destination that is not local. http:// was permitted to anything, so a caller that built a URL from an untrusted source could put a request body and a bearer token on the wire in the clear. Clear text is now allowed only where the traffic cannot leave the machine: a loopback address, the name localhost, a host pinned to a loopback address, and the Azure instance metadata address, which the platform defines as link-local and speaks clear text by design. A redirect to a destination that would move the traffic into clear text is refused as well, because a redirect is attacker-controlled input. The refusal names the scheme, the host and the port and nothing else, so a path or a query never reaches an error message.
  • A refused connection is no longer reported as a timeout. A request that fails while connecting carries two signals at once — the connect deadline expired, and the connection was never established — and the timeout was read first, so a write to a refused connection came back as DeadlineExceeded and asked the caller to reconcile an outcome that was never in doubt. The classification now lives in one place, transport_error::classify, and the order is the content of it: a cancellation outranks everything, a failure to connect outranks a timeout, and a timeout is what is left when the request was sent and the deadline passed.
  • The Azure CLI launcher is found whatever the case of its extension. The search compared the name it looked for against the name the directory held, so on a case-sensitive volume it found nothing. The comparison is now made against the names the directory actually holds, so the answer depends on the directory rather than on the host.
  • The Graph webhook test builds only when the Axum host is enabled, so the lean feature-matrix build compiles.
  • The newest Clippy is satisfied: map_unwrap_or and double_must_use are fixed rather than allowed. No behaviour changes.
  • The downstream performance harness counts in-flight requests rather than open connections in its peak metric. The gauge was taken at accept and held for the whole connection lifetime, so it reported work that had already finished as still running. Each gauge now has a binary of its own, because a sibling test’s runtime exists while the gauge holds its lock and moves the descriptor count the gauge asserts on.
  • The live descriptor gauge runs in a binary of its own for every gauge. The gauge that measures the peak metric was moved back beside the soak, so its three sibling tests ran in the soak’s process and moved the descriptor count the soak asserts on. The soak failed on a machine with two CPUs with 14 descriptors open against 10 before. Each gauge now has a process of its own, and the failure does not reproduce.
  • A checkout keeps the line endings the repository holds. A Windows runner checked the tree out with core.autocrlf set, which turned every LF into a CRLF, and the documentation tests compared bytes against files that are checked out with those same bytes. The repository now states its own rule — LF in the working tree, whatever the host’s Git is configured to do.
  • The documentation tests no longer depend on a line ending. The example was compared to the handler the test exercises byte for byte, and the README’s Rust block was found by a fence that had to end in a bare LF. A checkout that rewrote the endings made both look wrong on a machine where the code was right. The example is now compared line by line and the fence is matched by its text.
  • The host test that refuses an endless body no longer depends on the socket delivering the answer. The host stops reading a body it has already refused while the peer is still sending, so the connection closes with the answer half-written; Windows discards the queued bytes and the client is left with a reset and nothing at all. The status is now observed where the host produces it, which is the fact the test is about, and the client’s read is allowed to come back however the platform delivers it.
  • A queued notification whose one-to-one chat could not be read is given back instead of dropped. The service answered with an identifier the SDK cannot use, and the request that failed carried no message, so nothing was delivered. The outbox treated that as a permanent ending and finished the entry, which silently lost the notification. It is now transient, as the failure it replaced was, and a later round delivers it.
  • The Graph webhook test no longer races the queue it reads. A repeated notification was posted while the first delivery was still in flight, so it carried the same queue identifier and was refused at intake instead of being skipped at delivery. The test waited for the skip that could not arrive and timed out. The test now waits for the lane to empty before it posts the repeat, which is the state that makes the delivery path the one under test. A second test pins the other path: a repeat that arrives while the first is still in flight is refused at intake, and the handler still sees the notification once.
  • The installer scripts check what they claim to check. The shellcheck installer expanded the version inside a case pattern, so an archive whose name did not match fell through to a download that had no recorded digest; the name and the digest are now chosen together, so an archive without one cannot reach the download. The yamllint installer asked for a package that needs Python 3.10, and a machine whose default Python is older reported the package as missing rather than the interpreter as too old; the version is now checked and named.
  • Three tests no longer race a parallel test for a network port. Each found a free port by binding one and releasing it, which leaves the port free for any other test running at the same time to take. When one did, the test under question connected to that other test’s server instead of to nothing: the Connector test saw a connection that hung up mid-request and reported an ambiguous write rather than the refused connection it asserts, and the host test saw a bind that failed rather than the bind that succeeded. The tests now ask for port 0, which asks the kernel for a port that is free and cannot be taken by anyone else, and which is refused everywhere.

Changed

Section titled “Changed”
  • The feature matrix no longer exhausts a runner’s disk. It walked six feature sets and kept every one of them, which reached 8.5 GiB on a runner with 14 GiB and failed with No space left on device. The workspace’s own artifacts are now removed between combinations — they were 6.4 GiB of that total, and the dependencies are shared so they stay. The peak is about 2.8 GiB. The coverage measurement is unaffected.
  • The feature matrix’s peak was measured rather than estimated. It stood at 7.4 GiB, not the 4.2 GiB the documentation claimed, so the job was running with a third of the headroom it was believed to have. The incremental cache is now off, because the matrix builds each crate six times and reads the cache never, and the debuginfo is stripped from the linked artifacts. Stripping costs a reader nothing on a runner: a panic message names the file and the line from a constant compiled into the binary rather than from the debug information, so a failing test still says which line raised it. The peak is about 2.8 GiB, measured with the same environment the runner has.
  • The retry decision for a write now rests on a stated invariant: a Transport failure with no status means the request never reached the service. A request that reached the service and lost its answer is reported as AmbiguousWrite, a timeout is DeadlineExceeded, and a malformed response is InvalidRequest.
  • An answer that arrived but cannot be read is no longer reported as a transport failure. Opening a one-to-one chat whose identifier the SDK cannot parse now fails with the new TeamsError::UnusableResponse, because the service did answer and a transport failure with no status means the request never left. Nothing was delivered by that call, so the same idempotency key may try again. A channel thread that carried its first message is still reported as AmbiguousWrite, because the message may be in the channel.
  • The Linux jobs run on the organisation’s self-hosted runner rather than on hosted ones. The repository is private and the hosted runners are billed, so GitHub refused to schedule the jobs at all, and every run was red for a reason that had nothing to do with the code under test. The hosted legs that remain — macOS, Windows and Linux arm64 — are gated on a variable, so a skipped job never reaches the billing check.
  • A runner that does not carry a tool installs it. The runner is a plain Linux box, so shellcheck and yamllint are installed by a script rather than assumed. shellcheck matters because actionlint skips the run: blocks of a workflow when it is not on the machine, and a linter that quietly checks less than it appears to is worse than no linter.
