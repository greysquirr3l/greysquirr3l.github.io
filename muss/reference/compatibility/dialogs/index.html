Dialogs and message extensions

Search, selection, action commands, link unfurling and task modules are all invokes your bot answers inside the HTTP response of the request. This page records those surfaces and the application manifest the app is built from. No Teams client has run any of them.

Recorded 2026-11-11. These rows are the bot’s answers to invokes Teams sends: the SDK receives a signed activity and writes a response in the HTTP response of the same request. There is no Graph call, no token and no permission involved, so the permission type is none; the request is authenticated by the inbound authentication rows. Endpoint: the bot’s messaging endpoint. API version: the Bot Framework activity schema (these pages state no version). Cloud: Global only. Account type: single-tenant registration. “Task modules” are called dialogs in newer documentation; the wire names keep task/.

What the SDK does about each

Section titled “What the SDK does about each”
  • Typed and parsed once. The primary adapter reads each value into QueryRequest, SelectRequest, ActionRequest, LinkRequest or DialogPayload through FromStr/TryFrom newtypes (CommandId, ItemId, LinkUrl). A value that does not parse is answered 400 with no body and no hook or handler runs.
  • Authorization is the application’s, and the default is no. One hook sees all seven requests. With none registered every request is refused with a fixed message. A hook that fails also refuses.
  • Selection. The SDK writes { commandId, itemId } into each result’s tap and reads it back. That convention is the SDK’s: Learn’s sample uses { Item1, Item2, Item3 } because the bot chooses the tap value.
  • Bounds the SDK chose. 25 results per page; a larger count is lowered to 25, and the answer is cut to the request’s count; skip above 10,000 refused; 20 parameters, names of 64 and values of 512 characters; commands of 64 and item ids of 256 characters; dialog data of 64 KiB; responses of 512 KiB; text of 1,000 characters; dialog sizes of 1 to 10,000 pixels; 64 domain patterns. None is a Teams limit.
  • Deadlines. Default 4 seconds. A message extension invoke is held to Learn’s five seconds whatever is configured; task/fetch and task/submit are held to 30 seconds, an SDK choice. A late handler is cancelled at an .await; a link, which has nowhere to show text, is answered 504.
  • Domains. link_domains takes the manifest’s messageHandlers form: a * matches exactly one label, a top-level wildcard such as *.com is refused, and an empty list serves no link. dialog_domains is the same matching for validDomains; Learn says “Each url and fallbackUrl must implement the HTTPS encryption protocol”, and the SDK also refuses an address with credentials, a port other than 443 and an IP address.
  • No outbound fetch. The SDK never requests an address from a request. A test asserts the Connector stand-in saw no request after a link was unfurled.
  • Installed scope. interaction_scopes compares the authenticated activity’s conversation.conversationType with the scopes the app lists.
  • Errors the person sees. Refusals, timeouts and failures are a fixed message in the envelope the invoke expects, with HTTP 200, so Teams shows the text. That choice is the SDK’s.

Inconsistencies in the published pages

Section titled “Inconsistencies in the published pages”
  • The submit-action page’s prose spells the invoke composeExtensions/submitAction (with an s) while its JSON uses composeExtension/submitAction. The same happens for queryLink on the unfurling page. The SDK uses the JSON spelling and refuses the other.
  • Several action-command pages say commandContext “must be compose” while the command-box payload sample also shows compose. The SDK accepts compose, commandbox and message without case; that commandbox is ever sent is not confirmed.
  • task/fetch data is an object in most samples and a bare string in the Python sample (card_data = data.get("data") if isinstance(data, dict) else data); the SDK keeps either.
  • The dialogs page says the bot “receives a card.action activity” for task/fetch; the invoke name used everywhere else is task/fetch.

Not verified

Section titled “Not verified”
  • No Teams client has run any of this. Every shape comes from the pages and from fixtures; no search, selection, action command, dialog or unfurl was shown by desktop, web or mobile Teams against this SDK.
  • The dialog time budget. None of the pages read states one for task/fetch or task/submit; the five seconds is documented for query and submitAction only, and the SDK applies it to selectItem, fetchTask and queryLink as a precaution.
  • Result and payload limits. No page read states a maximum for results per page, attachments, or card size in a search response.
  • 403/404/504 for a link. The unfurl page defines result and auth only; how Teams treats an empty non-2xx answer is not stated.
  • Not implemented, deliberately: the auth, config and silentAuth response types, the grid layout, composeExtension/anonymousQueryLink (the response differs and the request may carry no signed sender), the setCachePolicy suggested action, and the settings invokes.
  • Outlook. The pages say Outlook does not support the bot-response Adaptive Card; the SDK does not detect the host.
