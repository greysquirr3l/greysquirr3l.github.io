Dialogs and extensions

Teams opens a dialog (called a task module before TeamsJS 2) from a card button or a link, and a message extension lives in the compose box: it searches, runs an action, or unfurls a pasted link. Both reach the bot as invoke activities, and the bot answers in the HTTP response of the request that carried them. muss-teams turns each into a typed async handler. You never build the invoke JSON.

The wire names keep the old word: task/fetch and task/submit are dialogs.

The shortest search extension

Section titled “The shortest search extension”

examples/search_extension.rs and examples/dialog.rs are complete programs. tests/example_dialogs.rs runs them.

What you register

Section titled “What you register”
Method Teams sends Your handler returns
on_dialog_open task/fetch DialogResponse
on_dialog_submit task/submit DialogResponse
on_extension_query(command, ..) composeExtension/query ExtensionResponse
on_extension_select(command, ..) composeExtension/selectItem ExtensionResponse
on_action_fetch(command, ..) composeExtension/fetchTask DialogResponse
on_action_submit(command, ..) composeExtension/submitAction ActionResponse
on_link(..) composeExtension/queryLink ExtensionResponse

command is the command id from your app manifest. A command that cannot be matched (empty, over 64 characters, or with whitespace) fails build.

Responses

Section titled “Responses”
  • DialogResponse::card(window, &card) shows an Adaptive Card dialog. DialogResponse::page(window, url, fallback) loads a page. DialogResponse::message(text) shows a pop-up and closes. DialogResponse::Done answers with no body, which is a valid answer to a submit.
  • ExtensionResponse::results(items) is a list of ResultItems. A query answer is cut to the request’s count (1 to 25), so a handler that ignores paging still sends one page. An empty list is sent as the message “No results found.” because Teams has no empty result. ExtensionResponse::message(text) is a plain message.
  • ActionResponse is another dialog, a result for the compose box, a BotPreview(card) (the person previews, then sends or edits; you see that as request().preview()), or ActionResponse::Done.

Not offered: auth and config responses, grid layout, anonymousQueryLink, and the composeExtension/* settings invokes.

Authorization, and why there is a hook

Section titled “Authorization, and why there is a hook”

A bot with no authorize_interactions hook denies every request. Teams tells you who is asking; it cannot tell you whether that person may read item pkg-9. The command, the item id, the form fields and the pasted address all come from the client and can be edited, so the hook is where “this belongs to this person” is checked. It runs before any handler, for all seven invokes, and gets an AccessContext whose request() is an InteractionRequest with operation(), command(), item(), url() and data().

A denial shows the person a fixed message in the envelope the invoke expects (or your Decision::deny_with text). A hook that fails denies. A link has no place to show a message, so it gets the status alone (403).

interaction_scopes([ConversationScope::Personal, ..]) also refuses requests from scopes the app is not installed for, and requests that name no scope, before the hook runs.

Domains and unfurling

Section titled “Domains and unfurling”
  • link_domains(["*.example.com"]) lists the domains on_link serves, in the manifest’s messageHandlers form. A wildcard matches exactly one label, the top-level domains are refused, and no domains means no links. A request whose address is not HTTPS, carries credentials, uses another port, is an IP address, or is on another host is answered 400 before any hook or handler.
  • dialog_domains([..]) is the manifest’s validDomains. A dialog that loads a page outside it is replaced with a generic message and reported to on_handler_failure. No domains means no page dialogs.
  • The SDK never fetches an address. The handler gets a LinkUrl and builds a card from your own data. If it fetches the address, it takes on the server-side request forgery risk the domain check only narrows; apply your own outbound policy.
  • Learn: only the first card of a link answer is used, link unfurling supports Adaptive Cards up to 1.3 (a newer card fails the request and is reported), and Teams caches the result for 30 minutes.

Bounds

Section titled “Bounds”
Bound Value Source
Results per page the request’s count, at most 25 (above is lowered); the answer is cut to it the sample’s count: 25; the maximum is the SDK’s
skip 10,000, above is refused with 400 SDK
Parameters 20, names 64 characters, values 512 SDK
Command id / item id 64 / 256 characters SDK
Dialog data 64 KiB SDK
Response body 512 KiB SDK
Handler time 4 s default; message extensions held to 5 s, dialogs to 30 s Learn gives 5 s to query and submitAction and retries twice; the dialog budget is not documented
Concurrency 16 default, past it 503 with Retry-After: 1 SDK

A handler past its deadline is cancelled (at an .await), the person sees “The app took too long to answer.”, and its concurrency slot is held until it is gone. A panic is contained. An error text never reaches the client.

State-changing submits

Section titled “State-changing submits”

ctx.once(material, |unit| ..) on a submit context runs work once for the operation, command and material, atomically with recording that it ran, and returns the stored result on a repeat. The same decision with different data is a conflict. It scopes keys to the tenant, and it cannot make a call to another system atomic: write an outbox entry from inside work. The default store is in memory; see Card actions for how long a decision lives.

Not verified

Section titled “Not verified”

No dialog, search, selection, action command or unfurl has been run in a real Teams client against this SDK. The response shapes come from Microsoft Learn and are checked by fixtures. The rows of the compatibility matrix that still need a live run are listed in the compatibility reference.

The full list of types, errors and settings is in the public API.
