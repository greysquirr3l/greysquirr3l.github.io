muss

Approachable Rust crates for Microsoft 365. The first crate, muss-teams, is a framework-neutral Teams SDK: one dependency, one facade, ordinary async functions. Where Microsoft's documentation leaves a question open, the SDK records the reading it chose, and marks what no live tenant has confirmed.

What you get

Section titled “What you get”

One dependency

An application depends on muss-teams and nothing else. The transport, the credential handling, the retry policy and the telemetry hooks are the crate’s problem, not yours. You write handler functions.

Typed handlers

Every activity kind gets its own context type and payload. A handler receives a typed value, not a JSON blob it has to guess about.

Adaptive Cards

A fluent builder for cards, and a reader that keeps everything it does not understand. Card actions arrive typed, and the bot denies by default until you say otherwise.

State that respects the tenant

A state store keyed by tenant and conversation, with compare-and-set, idempotent execution and an outbox. The outbox is at-least-once and says so.

Nothing claimed unverified

Every surface the SDK touches is recorded in the compatibility matrix with its endpoint, permission, cloud and the date it was checked. Where no live tenant has confirmed a behaviour, the matrix says so.
