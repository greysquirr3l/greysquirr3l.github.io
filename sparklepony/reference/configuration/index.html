Configuration reference

Sparkle Pony is configured entirely through command-line flags. There is no config file to edit and no environment variables to set. This page documents the internal configuration struct those flags populate, and the two places where a file is read from disk.

The Config struct

Section titled “The Config struct”

Every extract flag maps to a field on Config, built by the From<ExtractArgs> implementation in src/cli/mod.rs:

Field Flag Default
input_path --input / -i —
output_path --output / -o contacts.csv (see below)
cpu_limit --cpu 70.0
memory_limit --memory 70.0
min_free_memory_gb --min-free-memory 2
max_workers --workers / -w 0 (auto)
ignore_space_check --ignore-space-check false
temp_dir --temp-dir None (system temp)
safe_mode --safe false
debug_mode --debug false
disable_tld_filter --disable-tld-filter false
extract_attachments --extract-attachments false
chunk_size_mb --chunk-size 32
max_username_length --max-username-length 20
skip_senders --skip-senders false
skip_recipients --skip-recipients false
no_progress --no-progress false
exclude_ambiguous_roles --exclude-ambiguous false
blacklist_path --blacklist None (auto-resolved)

The full flag reference is on the CLI reference page.

Output path resolution

Section titled “Output path resolution”

The output path is not used verbatim. safe_output_path() re-roots a relative path when the working directory is not writable:

Situation Result
Working directory writable The path you gave, as-is
Working directory read-only, path absolute The absolute path, as-is
Working directory read-only, path relative Re-rooted at the user directory

The user directory is resolved in this order, taking the first that exists: Documents → Downloads → home → system temp.

The read-only case is not hypothetical. A macOS .app bundle launched from Finder runs with / as its working directory — the sealed system snapshot, which cannot be written to. Without this fallback, the first click in Neon Echo would fail with EROFS (os error 30).

default_output_path() follows the same rule when no --output is given: it returns contacts.csv in a writable working directory, and <user dir>/contacts.csv otherwise.

Progress and cache directory

Section titled “Progress and cache directory”

The resume file (.sparklepony_progress.json) and the TLD cache live in the input path’s parent directory when it is writable — co-located with the source data, so a run stays self-contained. When the source volume is read-only, they fall back to a per-user cache directory:

Platform Cache directory
macOS ~/Library/Caches/sparklepony/
Linux ~/.cache/sparklepony/
Windows %LOCALAPPDATA%\sparklepony\

Read-only source volumes are common in practice: a write-protected USB stick, or an NTFS volume mounted read-only on macOS.

Blacklist file resolution

Section titled “Blacklist file resolution”

The blacklist path is resolved by resolve_blacklist_path(). The first hit wins:

Order Location Notes
1 --blacklist <path> Explicit override
2 <cwd>/config/blacklist.ron The source-checkout convention
3 <config dir>/sparklepony/blacklist.ron Where the Neon Echo GUI saves its edits
4 Bundled defaults Compiled into the binary

The per-user config directory:

Platform Path
macOS ~/Library/Application Support/sparklepony/blacklist.ron
Linux ~/.config/sparklepony/blacklist.ron
Windows %APPDATA%\sparklepony\blacklist.ron

Step 3 is what makes GUI and CLI agree. An .app bundle has / as its working directory, so without a per-user location the GUI’s edits would never be picked up.

extract and exclude use the same resolution function, so the two can never disagree.

Blacklist file format

Section titled “Blacklist file format”

The file is RON — a single BlacklistConfig(...) call. Comments use // syntax.

List Matching Notes
blacklisted_terms Case-insensitive substring of the whole address Terms that cannot occur in a real name
bad_patterns Substring of the whole address ^ anchors the pattern to the start
role_local_parts Exact match on the local part Plus-addressing ignored
ambiguous_role_local_parts Exact match on the local part Opt-in via --exclude-ambiguous / --include-ambiguous
local_part_prefixes Prefix of the local part Automated senders
domain_suffixes Exact domain or any subdomain Bulk-mail infrastructure
domain_first_labels Leftmost label of the domain Marketing subdomains

Three domains are also excluded by a hardcoded floor that no file can change: arksf.com, smartofficesinc.com, mysmarthomes.com.

The blacklist guide walks through each tier with examples.

TLD validation

Section titled “TLD validation”

Domains are checked against the IANA TLD registry. The registry is cached locally between runs, in the same directory as the progress file, so a repeated run does not re-fetch it.

Pass --disable-tld-filter to skip this check entirely. It is the flag to reach for when you are working with a private or internal TLD that is not in the IANA list.

The single-instance lock

Section titled “The single-instance lock”

src/lock.rs takes a file lock so that two Sparkle Pony runs cannot write to the same output at once. The lock is released when the process exits, including on a crash.
