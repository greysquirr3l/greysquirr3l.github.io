Cleanup pipeline

Extraction filters as it goes, but it cannot check deliverability — that needs the network, and a run should not stall on DNS lookups. The three cleanup subcommands exist so you can run a second, independent pass over the CSV at your own pace.

They are ordinary Unix-style stages: each reads a CSV and writes two CSVs, and each takes the previous stage’s output as its input.

Stage 1 — syntax

Section titled “Stage 1 — syntax”

validate emails checks every address against RFC 5321/5322 syntax rules.

It reads from stdin by default, so it composes in a pipeline:

The rules it enforces:

Rule Detail
Local part length 1–64 characters
Domain length 1–255 characters
Exactly one @ A second @ in the domain is rejected
No spaces Anywhere in the address
No leading or trailing dot On the local part
No consecutive dots .. anywhere in the local part
Local part charset Alphanumerics plus + _ . - =
Domain has a dot user@localhost is rejected
Domain charset Alphanumerics, dots, and hyphens

Both outputs preserve the header row, and missing output directories are created for you.

--quiet suppresses the per-address INVALID: lines; --no-progress suppresses the bar. The bar is suppressed automatically when stderr is not a terminal.

Stage 2 — deliverability

Section titled “Stage 2 — deliverability”

validate mx checks whether each domain can actually receive mail, using DNS-over-HTTPS MX lookups. No messages are sent and no paid service is involved.

What it does:

  • Queries MX records through Cloudflare’s DoH endpoint on port 443, so it works anywhere HTTPS works
  • Falls back to A records when a domain publishes no MX, per RFC 5321
  • Detects null MX (0 .) per RFC 7505 — domains that explicitly refuse mail
  • Caches domains in memory, so each unique domain is queried exactly once
  • Is polite by default: capped concurrency and a per-cache-miss delay keep public DoH providers happy

Third-stage outputs

Section titled “Third-stage outputs”
File Contains
mx_valid.csv Addresses whose domain can receive mail
mx_invalid.csv Dead domains — NXDOMAIN, no mail records, null MX

A transient lookup failure is not the same as a dead domain. Pass --output-errors to keep errored rows in their own file rather than condemning them:

Tuning the politeness

Section titled “Tuning the politeness”
Flag Default Effect
--concurrency 6 Maximum concurrent DoH queries
--delay-ms 10 Delay after each new query per worker
--timeout 8 Per-request timeout, in seconds
--retries 2 Attempts per query, primary then fallback provider
--no-throttle off Removes rate limiting — fastest, but you may get throttled
--no-a-fallback off Disables the RFC 5321 A-record fallback
--stats-only off Prints stats without writing output files
--quiet off Suppresses progress output

The progress bar tracks unique domains resolved, not raw rows — only the first row for a given domain triggers a lookup. It shows the domain currently being queried.

Stage 3 — exclusion

Section titled “Stage 3 — exclusion”

exclude applies the blacklist to a contacts CSV and splits it into kept and excluded.

Add --explain to print each excluded address and the rule that removed it. The summary breaks the excluded count down by tier.

Flag Default
-i, --input - (stdin)
-o, --output-kept output/contacts_kept.csv
-x, --output-excluded output/contacts_excluded.csv
--blacklist auto-resolved
--explain off
--include-ambiguous off

See the blacklist guide for the tier rules.

Ordering, and why

Section titled “Ordering, and why”
Stage Question it answers Network?
validate emails Is this a well-formed address? No
validate mx Can this domain receive mail? Yes
exclude Is this a person worth contacting? No

Syntax first is deliberate: a malformed address cannot have a valid MX record, so checking it first keeps the network stage small. Exclusion last is deliberate too: the blacklist is about identity — is this a person or a mailing robot — while the first two stages are about validity. Running exclusion before MX validation would mean paying for DNS lookups on addresses you were always going to discard.
