ZIP and split PSTs

Outlook exports and mailbox dumps rarely arrive as one clean .pst. They come as ZIP archives, as split volumes that exceed a file-size limit, or as some mixture of both. Sparkle Pony accepts all of these without a separate unpacking step.

PSTs inside a ZIP archive

Section titled “PSTs inside a ZIP archive”

Point --input at the archive:

The extractor reads the archive’s central directory — a small metadata read, not the payload — and finds every PST-like entry inside it.

Stored entries are read in place

Section titled “Stored entries are read in place”

A ZIP entry can be Stored (uncompressed) or Deflated (compressed). Stored entries are the common case for PST archives, and they take the fast path: the PST bytes sit uncompressed at a known byte offset inside the archive, so Sparkle Pony opens the archive as a file, exposes that byte range through a seekable reader, and parses the PST straight out of it.

That means:

  • Zero extra disk space — nothing is expanded to a temporary file
  • Zero decompression time — the data is already flat on disk
  • No temporary-file churn on a machine that was low on space to begin with

Deflated entries fall back to a tempfile

Section titled “Deflated entries fall back to a tempfile”

A Deflated entry cannot be read at a fixed offset, so it is streamed into a temporary file that the extractor deletes when it is finished. The temp file is written to the system temp directory unless you point --temp-dir somewhere else:

Pointing --temp-dir at a fast, roomy volume is worthwhile when you are working with large compressed archives.

Several PSTs in one archive

Section titled “Several PSTs in one archive”

Every PST-like entry in the archive is processed. The source column in the output CSV records which archive entry each contact came from, so you can always trace a row back to its origin.

Multi-part split PSTs

Section titled “Multi-part split PSTs”

Some PSTs are too large for the filesystem or the transfer medium, so they are split into numbered volumes. Sparkle Pony detects and reassembles the common naming conventions automatically:

Naming shape Example
Numeric extension archive.pst.001, archive.pst.002
Leading-dot extension archive.001, archive.002
Numbered PST suffix archive.001.pst, archive.002.pst
Bare numbers archive.001, archive.002

Parts are matched by their logical key — the archive or base name with the numbering stripped — and ordered by their part number. The parts are then presented to the parser as one concatenated, seekable stream, so the PST parser sees exactly what it would see if the file had never been split.

Pointing at any one part is enough; the siblings are found next to it.

Parts spread across archives

Section titled “Parts spread across archives”

Split sets are sometimes zipped up before transfer, and sometimes the volumes land in different archives. The matching is by logical key rather than by directory, so archive.pst.001 inside part1.zip and archive.pst.002 inside part2.zip are still recognised as one logical PST:

Mixed input directories

Section titled “Mixed input directories”

The extractor classifies every file it meets as it walks, so a directory can hold loose PSTs, ZIPs, and split volumes at once:

Classification is per file, not per directory. A file that is not a PST, not a ZIP, and not a numbered part is skipped rather than treated as an error.

What you get in the output

Section titled “What you get in the output”

The source column records the shape each contact came from:

source value Meaning
archive.pst A loose PST file
mailbox.zip A PST entry inside a ZIP archive
archive.pst.001 A multi-part PST, named by its first part
